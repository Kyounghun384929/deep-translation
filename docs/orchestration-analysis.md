# 오케스트레이션 개선 분석 (v1.3.0 기준 · A1~A5·B1·B2는 v1.4.0에서 구현됨)

## 현재 파이프라인

```
단축키 훅 ──고정 대기(250/350ms)──▶ 클립보드 읽기(60ms×6 재시도)
  ──▶ TranslationWindow (디바운스 900ms, 시그니처 중복 방지, CTS 취소)
  ──▶ TranslationService (한국어 휴리스틱, 자동 모드 시 모델 후보 3개 폴백)
  ──▶ LlmGuard (전역 직렬화 1개, 냉각 250ms, 캐시 30분/32개)
  ──▶ LmStudioClient (SSE 스트리밍) ──▶ ThinkFilter ──▶ UI
```

취소 전파(창→CTS→HTTP), 게이트 대기 중 캐시 이중 확인, 요청 시그니처 중복 방지는
이미 잘 구성되어 있음. 아래는 남은 개선 여지.

## A. 요청 파이프라인 오케스트레이션

### A1. 클립보드 고정 대기 제거 — 효과 큼, 난이도 하 — **구현됨 (v1.4.0)**
`App.OnHotkey`가 250/350ms를 무조건 기다림. Win32 `GetClipboardSequenceNumber`를
20ms 간격으로 폴링해 값이 바뀌는 즉시 진행하면 평균 100~250ms 단축.
복사가 빠른 앱(메모장 등)에서 팝업 체감 속도가 눈에 띄게 개선됨.

### A2. 모델 목록 캐시 / 병렬화 — 효과 중, 난이도 하 — **구현됨 (v1.4.0)**
자동 모드에서 매 번역마다 `GetModelsAsync`가 게이트 안에서 직렬로 실행됨.
(1) 30초 TTL 캐시, 또는 (2) 클립보드 대기와 병렬로 미리 조회 — 둘 다 간단함.

### A3. `_lastWorkingModel` 영속화 — 효과 중, 난이도 하 — **구현됨 (v1.4.0)**
현재 static 메모리 전용이라 앱 재시작 후 첫 번역은 다시 후보 순회부터 시작.
`AppSettings`에 저장하면 재시작 직후에도 바로 성공 모델로 직행.

### A4. 취소 후 냉각 스킵 — 효과 소, 난이도 하 — **구현됨 (v1.4.0)**
`LlmGuard`의 250ms 냉각이 "이전 요청이 취소로 끝난" 경우에도 적용됨.
타이핑 중 연속 재번역 시 불필요한 대기. 취소 종료를 구분해 냉각을 건너뛰면 됨.

### A5. 스트리밍 UI 갱신 스로틀 — 효과 중(긴 글), 난이도 중 — **구현됨 (v1.4.0)**
토큰마다 `ThinkFilter.Strip(전체 문자열)` + `OutputBox.Text` 전체 재할당 → O(n²).
긴 번역에서 UI 스레드 부하 증가. 60~80ms 간격 배치 갱신으로 해결.

### A6. 캐시 키의 모델 정합성 — 효과 소, 난이도 하
캐시 키가 `settings.Model`(자동 모드 = 빈 문자열) 기준이라, 서버에 로드된 모델이
바뀌어도 30분간 이전 모델의 결과가 히트됨. 실제 사용 모델을 키에 반영할지,
단순성을 위해 현상 유지할지 결정 필요 (TTL이 있어 실해는 제한적).

### A7. 모델 워밍업 옵션 — 효과 큼(첫 번역), 난이도 중
첫 번역이 JIT 모델 로드를 포함하면 수 초~수십 초 걸림. 앱 시작 시 `max_tokens=1`
핑을 보내 미리 로드하는 **옵션**(기본 Off — 메모리 상주를 원치 않는 사용자 배려).

## B. LLM 다단계 오케스트레이션 (품질)

### B1. 감지+번역 단일 호출 구조화 — 효과 중, 난이도 중 — **구현됨 (v1.4.0)**
현재 언어 감지는 한글 비율 30% 휴리스틱뿐 → "일본어 원문인데 대상도 일본어"류의
언어쌍은 처리 못 함. 프롬프트로 첫 줄에 `[lang]` 태그를 출력하게 하면 추가 호출
없이 감지 결과 확보 → 원문=대상 언어일 때 보조 언어로 자동 전환 확장 가능.
(로컬 소형 모델의 JSON 출력은 불안정하므로 태그 방식 권장)

### B2. 용어집/스타일 주입 — 효과 중(반복 사용자), 난이도 하 — **구현됨 (v1.4.0)**
사용자 용어집(예: "LM Studio는 번역하지 않음")을 설정에 두고
`BuildSystemPrompt`에 주입. 오케스트레이션 변경 없이 프롬프트 조립만으로 가능.

### B3. 검수(고품질) 모드 — 효과 중, 난이도 중
번역 후 같은 모델로 자기 검수 1회를 돌리는 2-pass 옵션. LlmGuard 직렬 게이트와
자연스럽게 호환(순차 2호출). 시간 ~2배이므로 별도 버튼/옵션으로.

### B4. 긴 텍스트 분할 번역 — 효과 상황적, 난이도 상
문단 경계로 청크 → 순차 번역 → 이어붙여 스트리밍. 로컬 서버는 어차피 직렬이라
병렬 이득은 없음. 실익은 (1) 컨텍스트 한계 초과 방지, (2) 첫 토큰 도착 단축,
(3) 청크별 진행률 표시. 짧은 텍스트 위주 사용이면 우선순위 낮음.

### B5. 번역 이력 few-shot — 효과 소~중, 난이도 중
직전 확정 번역 1~2개를 예시로 프롬프트에 포함해 연속 문서 번역의 톤 일관성 확보.
캐시 키에 이력이 들어가면 히트율이 떨어지므로 키 설계 주의.

## 권장 순서

| 순위 | 항목 | 이유 |
|---|---|---|
| 1 | A1 클립보드 폴링 | 모든 번역의 체감 지연 직접 단축, 저위험 |
| 2 | A2+A3 모델 조회 캐시·영속화 | 자동 모드 오버헤드 제거, 몇 줄 수정 |
| 3 | A4 취소 후 냉각 스킵 | 연속 재번역 반응성 |
| 4 | B2 용어집 주입 | 품질 대비 구현 비용 최소 |
| 5 | A5 스트리밍 스로틀 | 긴 번역 안정성 |
| 6 | B1 감지 태그 | 언어쌍 커버리지 확장 |
| 7 | A7 워밍업 옵션 → B3 검수 모드 → B4 분할 | 옵션성 기능 |
